# iPhone Duo 到店取货监测

## 目的与范围
用户需要电脑关机后仍能收到手机补货提醒，无常开服务器，已有 GitHub 账号 deenhuang；手机为 iPhone，采用 Bark。
商品固定为用户链接 MK2P4CH/A（iPhone Duo 512GB 星光白色）。覆盖杭州 2 家和上海 8 家 Apple Store，不监测配送、不下单。

## 方案
曾比较 Mac 常开脚本与云端定时任务。用户选择手机提醒且无常开设备，因此采用 GitHub Actions + Bark；Python 标准库，无额外依赖，每 5 分钟调度，实际运行可能延迟。
仓库可见性待用户选择；默认不开启定时任务。私人账号的 GitHub Secrets 存放 BARK_KEY，密钥不提交、不打印。未配置推送时不能声称监测已就绪。

## 查询与可靠性
官网 /shop/retail/pickup-message 接口已在本机验证，分别查询 310000 和 200000 并按门店 ID 合并；/shop/fulfillment-messages 在本机返回 541，不作为可用依据。
仅产品 partsAvailability 的 pickupDisplay=available 视为可取货；unavailable 视为不可取货，其余值、无门店、缺商品、异常响应均为查询错误。
验证目标门店覆盖完整，苏州、宁波等附近城市不触发提醒。部分查询失败时保留失败门店的旧状态，并继续处理成功门店。
首次已可取货或由不可取货变为可取货时发送 Bark；持续有货不重复发送。推送失败不得标记已提醒。连续三轮异常发送故障提醒，每六小时最多一次；恢复后发送一次恢复通知。
状态保存在独立 monitor-state 分支，以免影响代码分支。GitHub 并发组防止两个监测写入同一状态。

## 验收
解析真实两地响应覆盖十家门店；离线测试覆盖补货、缺货、未知响应、部分失败、提醒失败重试、跨轮状态保存；云端手动检查必须成功。手机推送需用户配置 Secret 并收到测试通知后才能确认。
